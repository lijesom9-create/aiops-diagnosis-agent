# 数据库连接超时故障排查手册

| 文档属性 | 内容 |
| --- | --- |
| 文档分类 | troubleshooting |
| 文档版本 | v1.6 |
| 适用对象 | 运维工程师、后端开发 |
| 维护人 | DBA 组 + SRE 组 |

## 1. 故障现象描述

数据库连接超时类故障在生产环境高频出现，典型报错包括：

**应用侧报错：**

```
com.mysql.cj.jdbc.exceptions.CommunicationsException:
Communications link failure due to underlying exception:
** BEGIN NESTED EXCEPTION **
java.net.SocketTimeoutException: Connection timed out
** END NESTED EXCEPTION **
```

**连接池耗尽报错：**

```
HikariPool-1 - Connection is not available, request timed out after 30000ms
```

**数据库侧报错：**

```
ERROR 1040 (HY000): Too many connections
ERROR 1205 (HY000): Lock wait timeout exceeded; try restarting transaction
```

## 2. 影响范围评估

故障发生后需第一时间评估影响范围：

| 影响维度 | 评估内容 |
| --- | --- |
| 业务影响 | 哪些接口报错、是否影响交易下单、是否有资金损失风险 |
| 用户影响 | 影响用户数、是否有客诉 |
| 关联系统 | 是否触发上游调用方超时、级联熔断 |
| 数据一致性 | 是否有事务中断导致数据不一致 |

## 3. 排查步骤

### 3.1 检查数据库状态

```bash
# 登录数据库查看运行状态
mysql -h 10.0.1.21 -u admin -p

# 查看数据库启动时间和版本
mysql> SHOW GLOBAL STATUS LIKE 'Uptime';
+---------------+--------+
| Variable_name | Value  |
+---------------+--------+
| Uptime        | 864200 |
+---------------+--------+

# 查看数据库是否处于只读或恢复状态
mysql> SHOW GLOBAL VARIABLES LIKE 'read_only';
mysql> SHOW GLOBAL STATUS LIKE 'Slave_running';
```

### 3.2 检查连接数

```sql
-- 当前连接数
SHOW GLOBAL STATUS LIKE 'Threads_connected';

-- 最大连接数配置
SHOW GLOBAL VARIABLES LIKE 'max_connections';

-- 已使用的连接数 / 上限
SHOW STATUS LIKE 'Threads_connected';
SHOW STATUS LIKE 'Max_used_connections';

-- 查看每个客户端的连接数
SELECT host, COUNT(*) AS conn_count
FROM information_schema.processlist
GROUP BY host
ORDER BY conn_count DESC;

-- 查看连接错误
SHOW GLOBAL STATUS LIKE 'Aborted_connects';
SHOW GLOBAL STATUS LIKE 'Connection_errors_max_connections';
```

输出示例：

```
mysql> SHOW GLOBAL STATUS LIKE 'Threads_connected';
+-------------------+-------+
| Variable_name     | Value |
+-------------------+-------+
| Threads_connected | 1850  |
+-------------------+-------+
1 row in set (0.00 sec)

mysql> SHOW GLOBAL VARIABLES LIKE 'max_connections';
+-----------------+-------+
| Variable_name   | Value |
+-----------------+-------+
| max_connections | 2000  |
+-----------------+-------+
```

当 `Threads_connected` 接近 `max_connections` 的 80% 时即需告警。

### 3.3 检查网络连通性

```bash
# ping 测试网络延迟
ping -c 10 10.0.1.21

# telnet 测试端口连通性
telnet 10.0.1.21 3306

# nc 测试并查看 banner
nc -zv -w 3 10.0.1.21 3306

# mtr 查看网络链路
mtr -n -c 20 10.0.1.21
```

正常情况 ping 延迟 < 1ms（同机房）或 < 2ms（跨可用区）。若延迟抖动明显，需排查网络设备。

### 3.4 检查连接池配置

应用侧需确认连接池配置是否合理：

```bash
# 查看应用进程的连接数（按目标 IP 统计）
netstat -an | grep 10.0.1.21:3306 | grep ESTABLISHED | wc -l

# 查看应用创建的连接总数
netstat -an | grep 10.0.1.21:3306 | wc -l
```

### 3.5 检查慢查询

```sql
-- 查看当前正在执行的 SQL
SHOW FULL PROCESSLIST;

-- 查看慢查询是否开启
SHOW GLOBAL VARIABLES LIKE 'slow_query_log%';
SHOW GLOBAL VARIABLES LIKE 'long_query_time';

-- 查看慢查询数量
SHOW GLOBAL STATUS LIKE 'Slow_queries';
```

慢查询日志分析：

```bash
# 使用 mysqldumpslow 分析慢日志
mysqldumpslow -s t -t 10 /var/log/mysql/slow.log

# 使用 pt-query-digest 深度分析
pt-query-digest /var/log/mysql/slow.log > slow_report.txt
```

### 3.6 检查锁等待

```sql
-- 查看当前锁等待
SELECT * FROM information_schema.INNODB_LOCK_WAITS;

-- 查看锁信息
SELECT * FROM information_schema.INNODB_LOCKS;

-- 查看事务信息
SELECT * FROM information_schema.INNODB_TRX;

-- 查看死锁
SHOW ENGINE INNODB STATUS\G
```

若发现长时间未提交的事务，可定位到具体 SQL：

```sql
SELECT
    trx_id, trx_state, trx_started,
    trx_mysql_thread_id,
    trx_query
FROM information_schema.INNODB_TRX
WHERE trx_started < NOW() - INTERVAL 30 SECOND;
```

### 3.7 检查防火墙/安全组

```bash
# iptables 规则
iptables -L -n | grep 3306

# firewalld 规则
firewall-cmd --list-all

# 云安全组：在云控制台检查入站规则是否放行 3306 端口
# SELinux
getenforce
sestatus
```

## 4. 常用排查命令

| 命令 | 用途 | 示例 |
| --- | --- | --- |
| `SHOW PROCESSLIST` | 查看当前连接和执行的 SQL | `SHOW FULL PROCESSLIST;` |
| `SHOW STATUS` | 查看服务器状态 | `SHOW GLOBAL STATUS LIKE 'Threads%';` |
| `SHOW VARIABLES` | 查看配置变量 | `SHOW VARIABLES LIKE 'wait_timeout';` |
| `netstat` | 查看网络连接 | `netstat -an \| grep 3306` |
| `telnet` | 测试端口连通性 | `telnet 10.0.1.21 3306` |
| `tcpdump` | 抓包分析 | `tcpdump -i eth0 port 3306 -w mysql.pcap` |
| `ss` | 查看 socket 统计 | `ss -s` |

## 5. 根因分析表

| 症状 | 可能原因 | 验证方法 | 解决方案 |
| --- | --- | --- | --- |
| Connection timed out | 网络/防火墙阻断 | telnet 测试 | 开放安全组、检查 iptables |
| Too many connections | 连接池配置过大或泄漏 | SHOW STATUS LIKE 'Threads_connected' | 调整 max_connections、排查泄漏 |
| 连接池耗尽获取超时 | 慢查询占满连接 | SHOW PROCESSLIST | 优化慢查询 |
| Lock wait timeout | 事务未提交 | INNODB_TRX | kill 长事务、优化 SQL |
| 间歇性连接失败 | 连接数达上限 | Aborted_connects 增长 | 调大 max_connections |
| 连接立即断开 | wait_timeout 过短 | SHOW VARIABLES LIKE 'wait_timeout' | 调大 wait_timeout |
| 新连接报错 Host blocked | 同 IP 失败次数超限 | max_connect_errors | `FLUSH HOSTS;` 并调大阈值 |

## 6. 连接池配置最佳实践

### 6.1 HikariCP 推荐配置

```yaml
spring:
  datasource:
    hikari:
      # 最大连接数：核心公式 (core_count * 2) + effective_spindle_count
      # 通常 20-50，不要盲目调大
      maximum-pool-size: 30
      # 最小空闲连接：与最大连接保持一致，避免频繁创建
      minimum-idle: 30
      # 连接超时：30 秒，超时抛出异常
      connection-timeout: 30000
      # 空闲连接超时：10 分钟
      idle-timeout: 600000
      # 连接最大生命周期：30 分钟，定期重建避免长连接问题
      max-lifetime: 1800000
      # 连接有效性检测超时：5 秒
      validation-timeout: 5000
      # 连接泄漏检测：开启，超过 60 秒未归还记录日志
      leak-detection-threshold: 60000
      # 连接测试查询
      connection-test-query: SELECT 1
      pool-name: OrderHikariPool
```

### 6.2 Druid 推荐配置

```properties
# Druid 配置
spring.datasource.druid.url=jdbc:mysql://10.0.1.21:3306/order_db?useUnicode=true&characterEncoding=utf8&connectTimeout=3000&socketTimeout=30000&autoReconnect=true
spring.datasource.druid.username=app_user
spring.datasource.druid.password=${DB_PASSWORD}
spring.datasource.druid.driver-class-name=com.mysql.cj.jdbc.Driver

# 连接池核心参数
spring.datasource.druid.initial-size=10
spring.datasource.druid.min-idle=10
spring.datasource.druid.max-active=30
spring.datasource.druid.max-wait=30000

# 连接有效性检测
spring.datasource.druid.validation-query=SELECT 1
spring.datasource.druid.validation-query-timeout=5
spring.datasource.druid.test-while-idle=true
spring.datasource.druid.test-on-borrow=false
spring.datasource.druid.test-on-return=false

# 空闲连接回收
spring.datasource.druid.time-between-eviction-runs-millis=60000
spring.datasource.druid.min-evictable-idle-time-millis=300000
spring.datasource.druid.max-evictable-idle-time-millis=900000

# keepAlive 配置（保持连接活跃，防止被 DB 端关闭）
spring.datasource.druid.keep-alive=true
spring.datasource.druid.phy-timeout-millis=1800000

# 监控配置
spring.datasource.druid.stat-view-servlet.enabled=true
spring.datasource.druid.web-stat-filter.enabled=true
spring.datasource.druid.filter.stat.slow-sql-millis=1000
spring.datasource.druid.filter.stat.log-slow-sql=true
```

### 6.3 连接数计算参考

单个应用实例最大连接数推荐值：

```
maxPoolSize = (CPU 核数 * 2 + 磁盘数) ≈ 20~30
```

假设数据库 `max_connections=2000`，所有应用实例连接数之和应 ≤ 1600（保留 20% 余量）。

## 7. 慢查询优化

### 7.1 EXPLAIN 分析

```sql
EXPLAIN SELECT * FROM orders WHERE user_id = 12345 ORDER BY create_time DESC LIMIT 20;
```

输出示例：

```
+----+-------------+--------+------------+------+---------------+------+---------+------+--------+----------+-----------------------------+
| id | select_type | table  | partitions | type | possible_keys | key  | key_len | ref  | rows   | filtered | Extra                       |
+----+-------------+--------+------------+------+---------------+------+---------+------+--------+----------+-----------------------------+
|  1 | SIMPLE      | orders | NULL       | ALL  | NULL          | NULL | NULL    | NULL | 985632 |     1.00 | Using where; Using filesort |
+----+-------------+--------+------------+------+---------------+------+---------+------+--------+----------+-----------------------------+
```

关键字段解读：

| 字段 | 含义 | 优化关注点 |
| --- | --- | --- |
| type | 访问类型 | 至少达到 range，避免 ALL（全表扫描） |
| key | 实际使用的索引 | NULL 表示未走索引 |
| rows | 预估扫描行数 | 越小越好 |
| Extra | 附加信息 | 出现 Using filesort/temporary 需优化 |

上述 SQL 优化：添加联合索引 `(user_id, create_time)`：

```sql
ALTER TABLE orders ADD INDEX idx_user_create(user_id, create_time);
```

优化后 EXPLAIN：

```
+----+-------------+--------+------------+-------+-----------------+-----------------+---------+-------+------+----------+-------+
| id | select_type | table  | partitions | type  | possible_keys   | key             | key_len | ref   | rows | filtered | Extra |
+----+-------------+--------+------------+-------+-----------------+-----------------+---------+-------+------+----------+-------+
|  1 | SIMPLE      | orders | NULL       | ref   | idx_user_create | idx_user_create | 8       | const |   20 |   100.00 | NULL  |
+----+-------------+--------+------------+-------+-----------------+-----------------+---------+-------+------+----------+-------+
```

扫描行数从 98 万降到 20，消除 filesort。

### 7.2 SQL 重写建议

- 避免 `SELECT *`，只查必要字段
- 大分页用游标方案：`WHERE id > last_id ORDER BY id LIMIT 20` 替代 `LIMIT 1000000, 20`
- `IN` 子句控制元素数量 ≤ 500
- `JOIN` 字段必须有索引且类型一致
- 避免在索引列上使用函数或隐式类型转换

## 8. 预防措施

### 8.1 监控告警

| 监控项 | 阈值 | 告警级别 |
| --- | --- | --- |
| 数据库连接数使用率 | > 80% | P1 |
| 慢查询数（>1s） | > 100/min | P2 |
| 连接池等待线程数 | > 0 | P2 |
| 应用获取连接耗时 P99 | > 100ms | P2 |
| Aborted_connects 增长速率 | > 10/min | P3 |

### 8.2 定期巡检

- 每周检查慢查询 TOP 10，跟进优化
- 每月审查连接池配置与应用实例扩缩容是否匹配
- 每季度演练数据库主备切换，验证连接池自动重连

### 8.3 连接池配置审查 Checklist

- [ ] `maximum-pool-size` 不超过数据库上限的合理比例
- [ ] `connection-timeout` 设置合理（建议 3-30 秒）
- [ ] 开启 `leak-detection-threshold` 泄漏检测
- [ ] 开启 `test-while-idle` 空闲检测
- [ ] `max-lifetime` 小于数据库 `wait_timeout`
- [ ] JDBC URL 配置 `connectTimeout` 和 `socketTimeout`
