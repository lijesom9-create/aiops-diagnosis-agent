# 网络连通性故障排查手册

| 文档属性 | 内容 |
| --- | --- |
| 文档分类 | troubleshooting |
| 文档版本 | v1.7 |
| 适用对象 | SRE、网络工程师、后端开发 |
| 维护人 | SRE 组 |

## 1. 故障现象分类

网络故障按表现分为四类，排查方向各不同：

| 故障类型 | 表现 | 常见根因 |
| --- | --- | --- |
| 完全不通 | ping 不通、telnet 失败 | 网线断、IP 错配、防火墙拒绝 |
| 间歇性不通 | 时通时不通、随机超时 | 网络抖动、负载过高、连接数超限 |
| 延迟高 | ping 延迟大、响应慢 | 路由迂回、带宽打满、跨地域 |
| 丢包 | ping 出现 packet loss | 网卡故障、网络拥塞、MTU 不一致 |

## 2. OSI 七层排查法

按照 OSI 模型从下往上逐层排查，定位故障层级：

| 层级 | 排查内容 | 排查命令 |
| --- | --- | --- |
| 物理层 | 网线、光模块、网卡状态 | `ethtool eth0`、`ip link show` |
| 数据链路层 | ARP、MAC、VLAN | `arp -an`、`ip neigh` |
| 网络层 | IP、路由、ICMP | `ping`、`traceroute`、`ip route` |
| 传输层 | TCP/UDP、端口、连接状态 | `netstat`、`ss`、`tcpdump` |
| 会话层 | SSL/TLS 握手 | `openssl s_client` |
| 表示层 | 证书、编码 | `openssl x509` |
| 应用层 | HTTP/DNS/协议 | `curl`、`dig`、`nslookup` |

## 3. 常用网络排查工具

### 3.1 ping（网络层连通性）

```bash
# 测试连通性和延迟
ping -c 10 10.0.1.21

# 输出
# PING 10.0.1.21 (10.0.1.21) 56(84) bytes of data.
# 64 bytes from 10.0.1.21: icmp_seq=1 ttl=64 time=0.235 ms
# 64 bytes from 10.0.1.21: icmp_seq=2 ttl=64 time=0.198 ms
# --- 10.0.1.21 ping statistics ---
# 10 packets transmitted, 10 received, 0% packet loss
# rtt min/avg/max/mdev = 0.180/0.210/0.260/0.030 ms
```

关注 `packet loss`（丢包率）和 `time`（延迟）。正常机房内延迟 < 1ms，跨可用区 < 2ms。

### 3.2 telnet / nc（端口连通性）

```bash
# telnet 测试 TCP 端口
telnet 10.0.1.21 3306
# Trying 10.0.1.21...
# Connected to 10.0.1.21.
# Escape character is '^]'.

# nc 测试并显示 banner
nc -zv -w 3 10.0.1.21 3306
# Connection to 10.0.1.21 3306 port [tcp/*] succeeded!
```

### 3.3 curl（应用层）

```bash
# 测试 HTTP 接口，显示详细过程
curl -v --connect-timeout 3 --max-time 10 http://10.0.1.21:8080/api/health

# 输出
# *   Trying 10.0.1.21:8080...
# * Connected to 10.0.1.21 (10.0.1.21) port 8080
# > GET /api/health HTTP/1.1
# > Host: 10.0.1.21:8080
# < HTTP/1.1 200 OK
# * Connection #0 to host 10.0.1.21 left intact
```

### 3.4 traceroute / mtr（路径分析）

```bash
# traceroute 查看到目标的网络路径
traceroute -n 10.0.2.21

# mtr 实时路径分析（推荐）
mtr -n -c 20 10.0.2.21
# 输出示例
# HOST                  Loss%   Snt   Last   Avg  Best  Wrst StDev
# 1. 10.0.1.1            0.0%    20    0.3   0.3   0.2   0.5   0.1
# 2. 10.0.255.1          0.0%    20    1.2   1.1   0.9   1.5   0.2
# 3. 10.0.2.21           0.0%    20    1.8   1.7   1.5   2.3   0.3
```

`Loss%` 列能清晰显示哪一跳开始丢包。

### 3.5 tcpdump（抓包分析）

```bash
# 抓取目标 10.0.1.21 的 3306 端口流量，保存为 pcap 文件
tcpdump -i eth0 -w /tmp/mysql.pcap host 10.0.1.21 and port 3306

# 实时查看抓包内容（ASCII）
tcpdump -i eth0 -nn -A host 10.0.1.21 and port 3306

# 抓取 TCP SYN 包（连接建立）
tcpdump -i eth0 -nn 'tcp[tcpflags] & tcp-syn != 0' and host 10.0.1.21

# 抓取特定源端口
tcpdump -i eth0 -nn src port 12345

# 抓取 ICMP
tcpdump -i eth0 -nn icmp

# 常用过滤条件组合
# 抓取来源 10.0.1.0/24 到 10.0.2.21 的 80 端口
tcpdump -i eth0 -nn src net 10.0.1.0/24 and dst host 10.0.2.21 and dst port 80
```

抓取的 pcap 文件可下载到本地用 Wireshark 进行可视化分析：`File → Open`，使用 `tcp.stream eq N` 过滤单个 TCP 流，右键 `Follow → TCP Stream` 查看完整交互。

### 3.6 nslookup / dig（DNS 排查）

```bash
# nslookup 简单查询
nslookup api.example.com

# dig 查询 A 记录
dig api.example.com A +short

# dig 查询完整信息
dig api.example.com

# dig 追踪解析过程
dig +trace api.example.com

# 指定 DNS 服务器查询
dig @8.8.8.8 api.example.com

# 查询 CNAME
dig api.example.com CNAME +short
```

## 4. DNS 问题排查

DNS 故障常表现为：解析失败、解析慢、解析结果不一致、TTL 缓存问题。

### 4.1 完整排查流程

```bash
# 步骤 1：使用本地 DNS 查询
dig api.example.com +stats
# 关注 ;; Query time 字段，> 100ms 说明解析慢

# 步骤 2：使用公共 DNS 对比
dig @8.8.8.8 api.example.com +short
dig @114.114.114.114 api.example.com +short

# 步骤 3：追踪解析链路
dig +trace api.example.com
# 输出会显示从根域 → 顶级域 → 权威 DNS 的逐级解析过程

# 步骤 4：检查本地解析缓存
# Linux systemd-resolved
systemd-resolve --statistics
# nscd 缓存
nscd -g hosts

# 步骤 5：检查 /etc/resolv.conf
cat /etc/resolv.conf
# nameserver 10.0.0.53
# options timeout:2 attempts:3
```

### 4.2 DNS 缓存清理

```bash
# Linux nscd
nscd -i hosts

# systemd-resolved
systemd-resolve --flush-caches

# 应用层 JVM DNS 缓存（默认缓存 30 秒，HTTPS 场景需注意）
# Java 通过 networkaddress.cache.ttl 控制
```

### 4.3 TTL 问题

DNS 记录的 TTL 决定缓存时长。变更 DNS 记录前需提前调小 TTL：

```bash
# 查看当前 TTL
dig api.example.com +noall +answer
# api.example.com.  300  IN  A  10.0.1.21
#                    ^^^ TTL 300 秒
```

灰度切换场景：提前 24 小时把 TTL 从 3600 调到 60，确保切换时旧缓存快速失效。

## 5. TCP 连接问题排查

### 5.1 连接状态统计

```bash
# 查看所有 TCP 连接状态统计
netstat -n | awk '/^tcp/ {++S[$NF]} END {for(a in S) print a, S[a]}'
# 或使用 ss（更快）
ss -s

# 输出示例
# TIME-WAIT 32567
# ESTAB     8456
# SYN-RECV  23
# FIN-WAIT1 12
```

### 5.2 TIME_WAIT 过多

`TIME_WAIT` 过多会占用端口资源，导致无法新建连接。

```bash
# 查看 TIME_WAIT 数量
ss -ant | grep TIME-WAIT | wc -l
```

调整内核参数复用 TIME_WAIT 连接：

```bash
# /etc/sysctl.conf
net.ipv4.tcp_tw_reuse = 1          # 允许将 TIME-WAIT socket 重新用于新连接
net.ipv4.tcp_max_tw_buckets = 5000 # TIME_WAIT 最大数量
net.ipv4.tcp_fin_timeout = 30      # FIN-WAIT-2 状态超时
# 生效
sysctl -p
```

注意：`tcp_tw_recycle` 在 NAT 环境下会导致丢包，Linux 4.12+ 已移除该参数，不要开启。

### 5.3 连接数过高

```bash
# 查看单 IP 连接数 TOP
netstat -ntu | awk '{print $5}' | cut -d: -f1 | sort | uniq -c | sort -n | tail -10
```

### 5.4 SYN Flood 攻击

```bash
# 查看 SYN_RECV 状态连接数
netstat -an | grep SYN_RECV | wc -l

# 内核防护参数
# /etc/sysctl.conf
net.ipv4.tcp_syncookies = 1            # 开启 SYN cookies
net.ipv4.tcp_max_syn_backlog = 8192    # SYN 队列长度
net.ipv4.tcp_synack_retries = 2        # SYN+ACK 重试次数
```

### 5.5 KeepAlive 配置

长连接空闲过久被中间设备断开，需调整 KeepAlive：

```bash
# /etc/sysctl.conf
net.ipv4.tcp_keepalive_time = 600     # 空闲 600 秒后开始发送探测
net.ipv4.tcp_keepalive_intvl = 30     # 探测间隔 30 秒
net.ipv4.tcp_keepalive_probes = 3     # 探测次数 3 次
```

## 6. 防火墙问题排查

### 6.1 iptables

```bash
# 查看所有规则（带行号）
iptables -L -n --line-numbers

# 查看 NAT 表
iptables -t nat -L -n -v

# 查看某端口是否被规则放行
iptables -L INPUT -n | grep 3306

# 放行 10.0.1.0/24 访问 3306 端口
iptables -I INPUT -s 10.0.1.0/24 -p tcp --dport 3306 -j ACCEPT

# 拒绝某 IP
iptables -I INPUT -s 1.2.3.4 -j DROP

# 删除指定行规则
iptables -D INPUT 5

# 保存规则（CentOS）
service iptables save
# Ubuntu
iptables-save > /etc/iptables/rules.v4
```

### 6.2 firewalld

```bash
# 查看状态
firewall-cmd --state

# 查看已放行端口
firewall-cmd --list-ports

# 放行端口
firewall-cmd --permanent --add-port=3306/tcp
firewall-cmd --reload
```

### 6.3 云安全组

云上环境（阿里云/腾讯云/AWS）安全组是常见阻断点：

- 在控制台检查入站规则：源 IP、端口、协议
- 安全组变更可能延迟 1-2 分钟生效
- 跨可用区/跨 VPC 需检查对等连接和安全组双向规则

### 6.4 SELinux

```bash
# 查看 SELinux 状态
getenforce
# Enforcing  ← 会拦截未授权访问

# 临时关闭
setenforce 0

# 永久关闭
# /etc/selinux/config
# SELINUX=disabled

# 查看是否拦截了某端口
getsebool -a | grep httpd
audit2allow -a -m mypolicy  # 根据 audit 日志生成策略
```

## 7. HTTPS/SSL 问题排查

### 7.1 证书过期

```bash
# 查看证书有效期
echo | openssl s_client -connect api.example.com:443 2>/dev/null \
  | openssl x509 -noout -dates
# notBefore=Jan  1 00:00:00 2025 GMT
# notAfter=Jan  1 23:59:59 2026 GMT  ← 过期时间

# 一行命令查看剩余天数
echo | openssl s_client -connect api.example.com:443 2>/dev/null \
  | openssl x509 -noout -enddate | cut -d= -f2 \
  | xargs -I{} sh -c 'echo $(( ($(date -d "{}" +%s) - $(date +%s)) / 86400 )) days'
```

### 7.2 证书链不完整

```bash
# 检查证书链
openssl s_client -connect api.example.com:443 -showcerts 2>/dev/null \
  | grep -E "verify|depth"
# 若出现 "unable to verify the first certificate" 说明中间证书缺失
```

### 7.3 SNI 问题

一台服务器托管多域名时，必须正确发送 SNI：

```bash
# 指定 SNI 测试
openssl s_client -connect api.example.com:443 -servername api.example.com

# curl 测试
curl -v --resolve api.example.com:443:1.2.3.4 https://api.example.com
```

### 7.4 协议版本不支持

```bash
# 测试 TLS 1.2
openssl s_client -connect api.example.com:443 -tls1_2

# 测试 TLS 1.3
openssl s_client -connect api.example.com:443 -tls1_3

# curl 指定版本
curl -v --tlsv1.2 https://api.example.com
```

## 8. 负载均衡问题排查

### 8.1 健康检查失败

```bash
# 模拟健康检查请求
curl -v http://10.0.1.11:8080/health
# 若返回非 200，LB 会摘除节点

# 检查 Nginx upstream 状态
# 配置 stub_status
curl http://nginx-host/nginx_status
```

常见原因：健康检查路径错误、健康检查超时太短、后端节点负载过高响应慢。

### 8.2 会话保持失效

会话保持依赖 cookie 或源 IP，若失效会导致用户频繁掉线：

- 七层 LB：检查 cookie 配置，确认 cookie 未被应用覆盖
- 四层 LB：检查源 IP 保持，是否经过代理导致 IP 不一致

### 8.3 后端不可用

```bash
# Nginx 查看后端可用性
# error.log 中会出现
# upstream timed out (110: Connection timed out)
# no live upstreams while connecting to upstream
```

## 9. 常见根因总结表

| 症状 | 排查工具 | 可能原因 | 解决方案 |
| --- | --- | --- | --- |
| ping 不通 | ping、traceroute、ethtool | 网线断、IP 错配、网卡 down | 检查物理连接、`ip link set eth0 up` |
| telnet 端口不通 | telnet、nc、iptables | 防火墙拦截、服务未启动 | 检查安全组、启动服务 |
| 间歇性超时 | mtr、tcpdump | 网络抖动、连接数超限 | 排查中间链路、调整连接池 |
| 延迟高 | ping、mtr | 路由迂回、带宽打满 | 优化路由、扩容带宽 |
| 丢包 | ping、mtr、tcpdump | 网卡故障、MTU 不一致 | 更换网卡、调整 MTU |
| DNS 解析失败 | dig、nslookup | DNS 服务器故障、域名过期 | 切换 DNS、续费域名 |
| TIME_WAIT 过多 | ss、netstat | 短连接过多 | 开启 tcp_tw_reuse、改长连接 |
| SYN Flood | netstat、ss | DDoS 攻击 | 开启 syncookies、上游清洗 |
| 证书过期 | openssl | 未及时续签 | 监控告警、自动续签 |
| 证书链不全 | openssl | 中间证书缺失 | 补全证书链 |
| LB 摘除节点 | curl 健康检查 | 健康检查失败 | 排查后端服务状态 |

## 10. 预防措施

### 10.1 监控告警

| 指标 | 阈值 | 告警级别 |
| --- | --- | --- |
| 节点网络延迟 P99 | > 10ms | P3 |
| 节点丢包率 | > 1% | P2 |
| DNS 解析耗时 P99 | > 100ms | P3 |
| DNS 解析失败率 | > 1% | P2 |
| TCP 连接数 | > 50000 | P2 |
| TIME_WAIT 数量 | > 30000 | P3 |
| 证书剩余天数 | < 30 天 | P3，< 7 天 P1 |

### 10.2 证书自动续签

使用 cert-manager（K8s）或 acme.sh 自动续签 Let's Encrypt 证书，避免人工遗漏：

```yaml
# cert-manager Certificate 资源示例
apiVersion: cert-manager.io/v1
kind: Certificate
metadata:
  name: api-cert
spec:
  dnsNames:
    - api.example.com
  issuerRef:
    name: letsencrypt-prod
    kind: ClusterIssuer
  secretName: api-tls
  renewBefore: 720h  # 到期前 30 天续签
```

### 10.3 网络巡检

- 每日检查核心链路延迟和丢包率
- 每周核对安全组规则与实际需求是否一致
- 每季度演练跨可用区网络切换，验证容灾网络路径
