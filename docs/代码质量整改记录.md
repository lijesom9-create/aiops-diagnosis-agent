## 二·补、T2：裸异常人工甄别（收敛处理）✅

**结论**：AST 画像——`except` 共 450 处，其中"纯静默(pass/空)"52 处。逐一阅读后端核心后判定：**绝大多数是"合理降级的次要路径"，并非掩盖故障的危险吞错**。典型形态：

| 形态 | 实例 | 判定 |
|---|---|---|
| 指标埋点失败 | alerts.py `get_metrics().increment(...)` ×5、incident_ingest、token_counter | 指标采集不该打断主流程 |
| 临时文件清理 | parser/docling/multimodal/ocr 的 `os.unlink` | 清理失败无碍 |
| 超时轮询 | alerts.py `asyncio.wait_for` | 等唤醒信号，故意 |
| 解析兜底 | monitoring 时间格式、parser 编码 | 拉取兜底 |

**学习点**：静态扫描只能给"疑似"线索，"是否真问题"必须读上下文。机械补 error 日志/重抛会制造噪音，属错误方向。

**落地动作**（低侵入规范化）：为 9 处缺理由的"合理忽略"补 `# 为何忽略` 注释
- `backend/app/api/alerts.py` 7 处（指标埋点×6 + 轮询超时×1）
- `demo-service/faults.py`、`db.py` 各 1 处
- 验证：compileall 通过；diff 逐行审查确认只加注释、无逻辑变更。
